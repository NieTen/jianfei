# 群晖 Container Manager 局域网部署

此目录运行“并肩”的 Python 后台及 HTTPS 代理。NAS 直接拉取已构建镜像，不需要导入本地镜像、不需要 Java，也不需要在 NAS 上编译源码。iOS 模拟器 ZIP 和 IPA 是客户端，不能作为 Docker 镜像导入。

镜像地址：`ghcr.io/nieten/jianfei-api:latest`。支持 Linux AMD64 与 ARM64，由 Docker 选择匹配架构。发布流程先检查两种架构的后台测试、HTTPS 和数据保留，通过后才更新 latest。实际群晖设备还需执行下文验收。

## 一、准备目录与配置

1. 在 File Station 中创建共享目录下的 `docker/bingjian`，通常对应 `/volume1/docker/bingjian`。如果你的存储卷不同，以实际路径为准。
2. 将部署 ZIP 解压后的文件放入该目录，确保 `docker-compose.yml`、`Caddyfile`、`.env` 在同一级。
3. 如果从源码使用本目录，将 `.env.example` 复制为 `.env`；并创建 `secrets`、`certificates` 两个空目录。交付 ZIP 已包含这些目录和 `.env`。
4. 编辑 `.env`，将 `NAS_IP=192.168.1.10` 改成群晖的固定局域网 IP。它不是电脑 IP，也不包含 `https://`。
5. 默认 HTTPS 端口为 `8443`。如果已被其他服务使用，修改 `HTTPS_PORT`。开启 DSM 防火墙时，允许家中局域网访问这个 TCP 端口。
6. 建议设置至少 10 位的独立 `BACKUP_PASSWORD`，启用每日加密备份并另外保存密码。AI 配置可以先留空，之后在 App 中设置。

本配置绑定群晖的指定内网 IP；首次局域网测试不需要路由器端口转发。后台 8000 端口只在容器网络中使用，不映射到 NAS。

## 二、让群晖从私有仓库下载镜像

当前使用你自己的 GitHub 私有镜像仓库。拉取需要 GitHub 的个人访问令牌，不使用 GitHub 登录密码。创建 **Tokens (classic)**，只授予 `read:packages` 权限并设置有效期。令牌在 NAS 的登录提示中输入，不要发到聊天里，也不要填写到 `.env`。

[创建只读镜像令牌](https://github.com/settings/tokens/new?scopes=read:packages)；[GitHub 官方镜像认证说明](https://docs.github.com/en/packages/working-with-a-github-packages-registry/working-with-the-container-registry)。

Container Manager 的注册表搜索和“从 URL 添加”在不同版本对 GHCR 的支持存在差异。这里使用 SSH 登录并在线拉取一次，然后用图形界面的“项目”管理。

1. DSM 控制面板 → 终端机和 SNMP → 启用 SSH。
2. 在 Windows PowerShell 7 中连接，替换账号与 IP：

~~~powershell
ssh 你的群晖管理员账号@192.168.1.10
~~~

3. 以下命令在连接后的 **NAS 终端** 执行。`sudo -i` 输入群晖管理员密码；`docker login` 的 Password 提示中粘贴刚创建的 GitHub 令牌。

~~~bash
sudo -i
cd /volume1/docker/bingjian
docker login ghcr.io -u NieTen
docker compose --env-file .env -f docker-compose.yml pull
~~~

如果提示没有 `docker compose`，将最后一条命令换成 `docker-compose --env-file .env -f docker-compose.yml pull`。看到 api 与 caddy 均下载成功后即可退出 SSH。

这是在线下载镜像，NAS 不会构建源码。镜像仓库保持私有，部署过程不要求把项目公开。

## 三、在 Container Manager 创建项目

1. 打开 Container Manager → 项目 → 新增。
2. 项目名称填写 `bingjian`，路径选 `docker/bingjian`。
3. 使用目录里已有的 `docker-compose.yml`。如果界面要求选择来源，上传同一个文件。
4. 无需启用 Web Station 门户，本配置已包含 HTTPS 代理。
5. 完成并启动，等待 api 和 caddy 运行，其中 api 健康状态应变为 healthy。

群晖“项目”支持使用 Compose 文件创建并管理多个容器。[群晖官方项目说明](https://kb.synology.com/en-global/DSM/help/ContainerManager/docker_project)

如需全程使用 NAS 终端，启动命令为 `docker compose -p bingjian --env-file .env -f docker-compose.yml up -d`。两种方式保持相同项目名和路径，避免创建两套数据卷。

## 四、给手机安装 HTTPS 根证书

局域网 IP 使用本次部署生成的私有证书。手机必须信任它，App 才能通过 HTTPS 连接。

在 Container Manager 中选择本项目的 **caddy 容器**，打开终端，启动 `/bin/sh`，执行：

~~~sh
cp /data/caddy/pki/authorities/local/root.crt /certificates/bingjian-root.crt
~~~

File Station 的 `docker/bingjian/certificates` 中会出现 `bingjian-root.crt`。只把这个公开根证书发到自己的手机，不复制其他证书私钥。

在 iPhone 安装证书描述文件，然后进入“设置 → 通用 → 关于本机 → 证书信任设置”，开启该根证书的完全信任。仅安装描述文件还不够。[Apple 手动信任证书说明](https://support.apple.com/zh-cn/102390)

手机连到家中同一网络，在 Safari 打开 `https://你的NAS内网IP:8443/api/v1/health`，应显示包含 `"status":"ok"` 的 JSON，且没有证书错误。修改过端口时使用修改后的值。

## 五、注册与连接 App

在本项目的 **api 容器**终端中启动 `/bin/sh`，执行：

~~~sh
python -m app.cli enrollment
~~~

命令返回一次性开户凭据，有效期 24 小时，每个新账号分别生成。App 后台地址填写 `https://你的NAS内网IP:8443`，不要添加 `/api/v1`。完成地址测试后使用开户凭据注册，保存账号恢复凭据，再开启个人同步。

后台地址保存后会自动复用，后续在“我的 → 私有服务器与账号”修改。AI 地址、模型及密钥在 AI 设置中单独保存。

此后台提供 API，没有完整的浏览器版记录页面。`/api/docs` 是接口调试文档。Appetize 运行在云端，不能直接连接你家中的 `192.168.*` 等局域网地址；本方案用于同一局域网中的手机。Appetize 后台联调需另行配置它能访问的 HTTPS 地址。

## 六、更新、备份与常见问题

更新时重新在 NAS 登录 GHCR，进入同一目录执行 `docker compose -p bingjian pull`、`docker compose -p bingjian up -d`；旧版本使用 `docker-compose`。保持项目名为 `bingjian`，保留现有数据卷。不要通过“清理/删除项目”升级，不要执行带 `--volumes` 的停止命令。数据库、照片与内部密钥在 app_data 卷，证书在 caddy_data 卷；日常重启和重建容器会复用它们。

镜像不会自动重启更新已有容器，需要你主动拉取并重建。自动备份保存在同一数据卷内，建议另行复制到其他位置；完整备份和恢复流程见仓库 `docs/部署与运行.md`。

| 现象 | 处理 |
| --- | --- |
| `unauthorized`、`denied` | 用 `sudo -i` 后重新登录 GHCR；检查 classic 令牌的 `read:packages` 权限、账号和有效期 |
| 连接 `ghcr.io` 超时 | 检查 NAS 的 DNS、网络和代理；这不是 Compose 格式问题 |
| 找不到镜像或 `manifest unknown` | 确认镜像发布流程已成功，地址为 `ghcr.io/nieten/jianfei-api:latest` |
| 端口已占用 | 修改 `.env` 的 HTTPS_PORT，再重建项目；App 使用相同新端口 |
| 无法分配请求的地址 | NAS_IP 不是这台群晖当前拥有的内网 IP，修正后重建项目 |
| api 不健康 | 查看 api 日志，检查资源、磁盘空间；保留完整错误信息 |
| iPhone 提示证书不受信任 | 核对访问 IP，完成描述文件安装和“完全信任”两步 |
| Appetize 连接内网失败 | 云端无法直接访问家庭内网，使用同网手机或另行配置可达地址 |
| 浏览器打开根路径返回 404 | 属于 API 服务，使用 `/api/v1/health` 检查是否启动 |
