# 云端功能补全与验证

2026 年 11 月 19 日，在 `f72ac6e` 的基础上补全记录性能、云账号与 SVIP、备份迁移、分享共享。以下验证在隔离的测试目录中执行。生产部署和打包不在本次操作范围内。

## 用户入口

| 需求 | 操作入口 | 结果 |
| --- | --- | --- |
| 云账号 | 我的 → 云端账号与 SVIP | 邮箱注册、登录与找回。新客户端在注册前展示云同步规则。选择关联未绑定记录前展示数量和日期。设备被撤销后，需要密码和专用邮箱验证码才能重新登记。 |
| AI 识图 | 有效 SVIP 的餐次编辑和云端 AI 设置 | 服务端保管模型和密钥，在任务提交和执行时检查权益、授权。离线撤回会按服务器实例和账号保存在本机，重启后仍拦截新识别，联网后优先送达撤回。普通账号可继续手动记录和同步照片。 |
| 手机历史备份 | 我的 → 导出、恢复与删除 | 为当前本地空间保存可恢复的加密版本。照片尚未下载时显示缺少的数量，保留照片关系。跨手机恢复可使用自选密码的个人导出包。 |
| NAS 或离线记录迁移 | 登录目标云账号 → 我的 → 导出、恢复与删除 → 从旧 NAS 或未绑定离线空间迁入 | 选择未绑定的离线空间，或从已登录的旧账号导出并解密个人归档。核对来源、目标、日期、记录和照片后再确认写入。源数据保留。 |
| 挑战邀请 | 伙伴 → 创建挑战 → 分享邀请 | HTTPS 部署提供通用链接。已安装时进入 App，未安装时显示轻量网页及邀请码。未登录时保留邀请，登录后预览并主动确认加入。现有局域网 HTTP 部署仍可使用二维码、自定义链接和邀请码。 |
| 成果卡片 | 伙伴 → 分享我的记录卡片 | 预览本机生成的卡片，经系统分享面板发送。卡片只显示日期、已记录餐次数及当天是否记录体重，不带实际体重、原始照片或备注。 |
| 指定账号共享 | 伙伴 → 共享中心 | 选择接收账号、记录日期、访问到期时间及允许的字段。体重、饮食摘要、明细、照片、备注分别授权。接收人在共享中心在线查看，无需 SVIP。共享中心支持修改和撤销。 |

## 同步和隐私边界

- 同步状态详情继续分页。后台同步分批读取命令、照片和快照核对项，只有收到确认的命令才出队。撤权命令优先，任务取消后可重试。
- 通用共享的摘要、原图和缩略图均核验接收人、照片归属、日期和有效期，且不写入接收人的个人记录。服务器确认撤销后拒绝新的读取。已打开的通用详情至多每分钟重验一次，到期会清空。用户主动发送到其他应用的卡片由接收方持有。
- 伙伴挑战兼容已有缓存，新客户端把可显示时长限制在五分钟内。仅在断网等连接故障时可读尚有效的摘要。权限拒绝清空缓存。按账号重建伙伴导航，迟到的响应不能写入后切换的账号空间。
- 个人数据先落本机，启用同步才会上传。清空个人数据或注销会同时清理收发共享授权。恢复服务器旧备份会撤销通用共享及旧挑战邀请码，需要重新授权。
- 基础账号与 SVIP 的边界在 `DEPLOYMENT_MODE=cloud` 生效。私有 NAS 可继续使用原有 AI 配置。会员可由管理员授予和撤销，应用内收费仍按原方案作为可选阶段。

本机自动版本最多保留七份，App 在启动或保存后有机会运行才会创建。服务器副本需挂载独立存储并配置备份密码。旧包恢复需要核对独立删除账本，完整操作见[阶段 C 备份迁移与恢复](阶段C备份迁移与恢复.md)。

第一版的健康数据在线共享限指定账号。公开匿名健康报告链接和 App Store 付费购买仍是原方案中的可选扩展。

## 正式 HTTPS 邀请配置

在有公网域名时填写以下部署值。内网测试沿用现有配置即可。

| 配置项 | 用途 |
| --- | --- |
| 服务端 `PUBLIC_URL`、iPhone 构建项 `BINGJIAN_CLOUD_SERVER_URL` | 填写同一 HTTPS 服务地址。域名根路径须能访问 `/join`、`/invite.js` 及 `/.well-known/apple-app-site-association`。 |
| 服务端 `IOS_APPLICATION_ID` | 填签名描述文件中的完整应用标识，即 App ID 前缀与 Bundle ID 的组合。关联文件会返回此标识。 |
| iPhone 构建项 `BINGJIAN_IPHONE_ENTITLEMENTS` | 公网构建选 `BingJian/CloudLinks.entitlements`。`BINGJIAN_LINK_DOMAIN` 填相同域名的主机名。App ID、签名描述文件需要包含 Associated Domains 能力。 |

邀请令牌放在 URL 片段中，浏览器请求和链接预览不会消费单次码。域名关联生效依赖公开 HTTPS、正确的签名和 Apple 的域名关联服务。[Apple 域名关联说明](https://developer.apple.com/documentation/xcode/supporting-associated-domains)

## 本轮实测

| 检查 | 结果 |
| --- | --- |
| Python 3.13 后台回归 | 106 项通过。覆盖普通云账号通过邮箱共享、无 SVIP 时拒绝识图、跨账号隔离、授权撤回和到期、媒体访问，以及异地副本与删除账本恢复。 |
| macOS 原生 Swift XCTest | 35 项通过，包含记录重载与同步 22 项、云账号与共享规则 8 项、本地版本备份及迁移 5 项。 |
| 记录性能 | Apple M5 Pro 上，一万条业务记录中保存一条后只读取一条变更正文，连同内存索引合并约 8 毫秒。十万条离线命令分页遍历约 2.08 秒，十万张照片中取得首批 50 张可同步照片约 25 毫秒。 |
| 灾难恢复 | 在临时目录使用独立副本和最新删除账本，从空数据卷恢复旧备份。原账号仍在，较晚删除的记录未恢复，旧会话失效。模拟卸下副本目录后，本地包仍能生成，必需的异地验证报告失败。 |
| 跨语言归档 | 10 类虚构业务记录及一张 235,765 字节的合成 JPEG 完成 Python 导出、Swift 解密和迁移、Swift 导出、Python 导入预览。验证了公斤数值、未知营养、中文、照片哈希与证据关联，重复迁移预览识别出 10 条相同记录。 |
| 邀请与编译 | 本机 Chrome 验证落地页有效码回跳及缺码提示。Xcode 27.2 的 iPhone、Watch 设备目标编译通过，模拟器测试目标也通过 `build-for-testing`。 |

日常保存可增量更新索引。首次打开数据库或发生大批变化时，仍会全量构建全局索引。以上设备性能为 macOS 测量。

真机帧率和峰值内存、签名设备上的 Universal Links、两部 iPhone 断网重连、真实邮箱和 AI 提供方、实际 NAS 异地存储均需在目标环境验收。代码中的双备份能力需要配置独立存储、备份密码并能取回密钥，单纯打开个人同步不会产生异地副本。
