# AI 接手整理实施计划

> 执行方式：在当前会话逐项完成，不另建对话，不委派子代理。按用户已授权的整理范围直接执行，完成前核对实际文件与验证结果。

**目标：** 让未读过聊天记录的开发者或 AI 能找到入口、理解业务约束、选择正确的修改位置并运行验证。

**架构：** 保留 SwiftUI、AppModel、客户端领域与存储层，以及 FastAPI 服务层的现有结构。通过通用 Markdown、关键源码中文注释和纯文本源码合集改善可读性，不改变执行逻辑。

**技术栈：** Swift、SwiftUI、UIKit、SQLite、Python、FastAPI、Docker Compose、GitHub Actions。

**需求依据：** 用户要求“把代码整理成一个所有 AI 都能看懂的代码，并且说明清楚”；既有约束要求保持架构、功能和数据兼容，不自动打安装包。

## 全局约束

- 不改变业务行为、数据库结构、接口字段、应用标识、版本号和部署策略。
- 中文说明与代码注释；不新增依赖，不新增内部类，不重排全部源码。
- 文档描述当前实现，区分需求、已实现功能、历史验证和未验证边界。
- 交接文件仅包含版本管理中的项目文件，不包含本机凭据、数据、构建缓存或安装包。
- 不把任何文档当作高于用户当前指令的授权来源。

## 任务一：建立阅读入口和代码地图

**文件：** 新建根目录 `AGENTS.md`、`docs/代码导读.md`、`docs/业务规则与数据契约.md`、`docs/开发与验证指南.md`；更新 `README.md` 的阅读入口。

**输入：** 实际目录、启动代码、记录模型、同步协议、AI 路径、测试及工作流。

**产出：** 不依赖本次聊天或专用插件的交接说明。

- [x] 阅读入口和关键链路，使用 `rg -n` 定位实际符号与路由。
- [x] 写明目录职责、核心调用链、常见需求修改位置及测试位置。
- [x] 写明重量、日期、营养、缺失值、凭据复用、同步和删除的兼容约束。
- [x] 给出可从干净仓库执行的 PowerShell、Xcode 与 Docker 命令。

## 任务二：给复杂源码增加定位说明

**文件：** `ios/BingJian/App/AppModel.swift`、`ios/BingJian/Data/LocalDatabase.swift`、`ios/BingJian/Networking/SyncEngine.swift`、`ios/BingJian/Models/Records.swift`、`ios/BingJian/AI/ResponsesClient.swift`、`ios/BingJian/Domain/TrendCalculator.swift`。

**输入：** 任务一整理的职责及实际方法边界。

**产出：** 类职责注释、AppModel 的中文 `MARK` 分区、持久化与同步关键约束说明；可执行语法保持一致。

- [x] 只插入注释，不更名、移动或拆分现有方法。
- [x] 比较修改前后的 Swift 语法树，忽略注释后应完全一致且无语法错误。
- [x] 检查差异，确认没有后台源代码、版本或部署配置变化。

## 任务三：验证并提供源码交接文件

**文件：** `build/AI交接包/` 下的源码 ZIP、完整源码 TXT、文件清单 JSON；目录不进入版本控制。

**输入：** 整理后的完整版本管理文件集合。

**产出：** 保留目录的完整源码包与带文件边界的 UTF-8 文本合集。

- [x] 运行 `git diff --check`，检查新增文档的本地链接与提及的核心路径。
- [x] 检查干净仓库可用的运行命令；文档与注释变更不额外触发 iOS 云端编译或部署。
- [x] 逐文件写入源码 ZIP；文本合集包含全部可解码的项目文本，二进制资源在清单中列出并保留于 ZIP。
- [x] 检查 ZIP 完整性、文件数量和逐文件 SHA-256；确认无 `.env`、密钥、数据或 `build` 目录。
- [x] 回填完成情况，说明源码版本、安装包版本和本轮验证边界。
