# 阶段 C：个人备份、独立副本与迁移

本文件说明当前源码的阶段 C 能力及运维入口。没有配置真实独立存储、保管密码和完成目标环境恢复演练前，不能将“本机有记录、服务器也有记录”宣传为已经具备可靠双备份。本轮没有部署、推送或访问生产数据。

## 本机版本备份

“我的 → 数据管理”默认启用当前空间的自动版本备份。首次载入或业务记录变化后延迟 5 秒合并触发；每 6 小时最多自动生成一版，保留最近 7 个成功版本。首次空库不生成占用时间窗口的空备份；手动“立即创建本机版本”不受该间隔限制。iOS 不保证 App 被终止后仍可定时运行，因此它是 App 运行期间的保存后备份，不是全天候系统服务。

备份以一致的只读数据库修订取得业务记录、删除标记和已下载照片，使用现有 BJAR2 分片认证加密，完成后再次解密校验。源目录之外的 `Application Support/BingJianBackups/<namespace>` 保存版本和状态，明确排除系统备份并设置设备数据保护。包不包含登录凭据、AI 密钥、伙伴共享缓存、共享授权、离线授权命令或同步游标。

未下载的照片不会阻止自动版本备份：包保留照片引用，清单保存 `missing_photo_ids`，页面显示缺图数量。这种包不能独立恢复缺少的照片，必须从仍可访问的原服务补齐。用户主动“导出本机完整记录”并勾选照片时仍严格要求照片齐全，不将部分成功伪装成完整导出。

本机版本密钥按空间保存到本机 Keychain，应用不回显密钥；已有备份而密钥不可读时不会自动新建另一个密钥。密钥只适用于当前设备，跨设备恢复需要另外导出用户自选密码的个人包，并将包与密码分开保管。

选择版本只打开校验后的恢复预览，确认后才写入。导入前自动保留目标空间保护版本；预览之后目标内容变化时，事务整体拒绝并要求重新预览。默认保留当前记录，当前删除标记优先；用户显式选择将已删除记录另存时生成新 ID，不能无意复活旧记录。恢复合并业务内容并重新形成个人同步操作，不恢复旧登录、共享命令或游标。

清除当前活动副本与删除备份是两个明确操作。页面“删除当前空间的版本与迁移备份”会删除该空间本机版本、内部保留的迁移来源包和对应备份密钥，并关闭自动备份；不会删除用户另存到文件 App 的副本。注销服务器账号同样不会自动销毁用户已经导出的文件。需要不再保留时，应先使用本机删除备份操作，再自行删除另存文件。

## 云端独立副本

继续复用原有每日备份、完整/增量归档、附件去重、30 天保留及恢复完整性校验，新增可选的独立目录复制：

| 配置 | 作用 |
| --- | --- |
| `BACKUP_PASSWORD` | 至少 10 位独立密码，用于备份及独立删除账本加密 |
| `BACKUP_HOUR` | 服务时区的每日备份开始小时，默认 3 |
| `BACKUP_REPLICA_DIR` | 预先挂载、与 `DATA_DIR` 不互相包含的目录；每实例使用独立目录 |
| `BACKUP_REPLICA_REQUIRED` | 为 `true` 时，异地复制失败使任务失败并重试；不会把仅本机成功当成完整成功 |
| `BACKUP_REPLICA_HOST_DIR` | 使用附带 Compose 覆盖文件时的主机挂载目录 |

代码校验目录独立和复制完整性，不能证明两个目录位于不同物理磁盘或故障域。运维必须将目标指向另一设备、异地文件系统或独立受保护存储，而不是同一数据盘的另一个文件夹。程序要求目录已经存在；附带覆盖文件禁止自动创建缺失的主机路径。启用前验证远端挂载的故障行为、配额和访问权限。

配置副本后，每份本机已校验包和对应 `.refs.json`、必要的 `objects/` 会复制并校验哈希，再从副本实际解密检查文件和 SQLite 完整性。`latest.json` 仅在副本验证成功后更新。`app.cli status` 返回是否配置/要求副本及 `last_backup.replica`，失败信息不会包含密码。配置为非必需时可能出现“本机成功、副本失败”，应以 `verified` 字段判断。

每日任务的失败重试复用该任务已验证的本机包及引用，不会每 5 分钟重新制造一份大包。原有重试上限为 5 次，失败需运维修复后重试或手动备份；次日仍会创建新的每日任务。副本保留期与本机系统备份一致，为 30 天；仍被保留包引用的增量对象不删除。

### Docker 配置示例

先挂载独立存储，再在本地 `.env` 配置真实密码及主机路径；不要将 `.env` 提交进仓库。`BACKUP_REPLICA_HOST_DIR` 指向已经挂载的实例专用子目录，`BACKUP_REPLICA_REQUIRED=true`。

```bash
docker compose -f compose.yaml -f compose.backup.example.yaml config --quiet
docker compose -f compose.yaml -f compose.backup.example.yaml up -d --build
docker compose -f compose.yaml -f compose.backup.example.yaml exec api python -m app.cli backup --full
docker compose -f compose.yaml -f compose.backup.example.yaml exec api python -m app.cli status
```

Compose 覆盖文件将容器内副本路径设置为 `/backup-replica`。群晖使用相同环境变量和独立 bind mount 原理，但应在自己的 Compose 项目配置中加入对应目录映射，不能把容器路径误写成主机路径。

## 独立删除账本与空卷恢复

启用副本后，每次已验证的删除意图在事务确认前同步写入副本根目录的 `deletion-intents.encrypted.jsonl`，采用随机 nonce 的 AES-GCM 逐条认证加密，并执行 `fsync`。旧本机删除意图在首次启用时补入独立账本。账本不可用时删除不能向调用方确认成功；业务数据和删除事务仍会回滚。备份任务失败不会删除已完成的本机包。

如果目录已有 `latest.json` 或备份包却缺少独立账本，启动会明确拒绝，不能静默创建空账本后恢复旧数据。账本密码或内容损坏同样报错。独立账本不随 30 天备份轮换自动删除；它只保存防止恢复复活所需的最小删除标识，不包含餐食正文或照片。请独立保护它，不要用旧备份覆盖它。

本轮生成的副本备份还在加密清单中记录独立账本 ID。即使将包复制到其他目录，恢复时仍要求挂载原账本；新建的空账本不能冒充原账本。历史未启用独立账本的旧包没有这个字段，兼容恢复仍需运维核对最新删除来源，不能据此声称具备灾难恢复后的删除保护。

恢复时同时读取现有本机账本和副本最新账本，替换数据库后重放删除，再失效旧会话、同步 epoch、共享授权；云权益按现有规则冻结待管理员重新核实。即使原 `DATA_DIR` 整个丢失，仍能从副本的旧包和保留的新删除账本恢复，并排除旧包之后已删除的数据。

操作前停止 API，并确认已挂载包含最新账本的副本目录。完整包可单文件携带业务与附件；增量包还必须保留相邻 `objects/` 或使用 `--objects` 指定对象目录。下列文件名应替换成 `latest.json` 中经过核对的实际包名：

```bash
docker compose -f compose.yaml -f compose.backup.example.yaml stop api
docker compose -f compose.yaml -f compose.backup.example.yaml run --rm --no-deps api \
  python -m app.cli restore /backup-replica/backups/已核对的备份.bjar
docker compose -f compose.yaml -f compose.backup.example.yaml up -d api
docker compose -f compose.yaml -f compose.backup.example.yaml exec api python -m app.cli status
```

使用全新数据卷演练时，必须仍指向保留最新独立账本的副本目录，并使用原备份密码。不要仅复制旧 `.bjar` 后配置一个空副本目录，也不要在原目录上直接更换 `BACKUP_PASSWORD`；已有包及账本需要原密码解密。密码轮换应另行制定带验证的迁移流程。

## 旧 NAS 与离线记录迁移

“数据管理 → 从旧 NAS 或未绑定离线空间迁入”包含目标说明、来源选择、加密副本保留、条数/日期/照片/冲突预览及抽样、显式归属确认、迁移前目标保护版本和迁移后标识核对。

- 迁入云账号前先登录目标账号。系统不自动开启个人同步。
- 未绑定本机离线空间可以只读选取；已绑定其他账号的本机目录不列出，也不能直接读取。持有设备上的目录不代表拥有来源账号权限。
- 旧 NAS 或其他绑定账号须先在原服务认证，导出包含照片的个人加密包，再提供该包及密码。向导不索取或转发旧账号令牌。
- 迁移使用来源身份、目标身份和旧记录/照片 ID 的确定性映射；相同来源重复导入不生成重复实体。已有健康 `source_id` 优先匹配，公斤数值不转成显示单位。餐次与收藏食物的照片证据一起重映射；旧 AI 任务 ID 和内部结果元数据清除，历史食物及营养保留。
- 保留删除语义，预览后目标发生修改时整体拒绝写入；网络断开或 App 中断后可以重新选择同一来源继续。本地写入是事务，随后按现有同步队列续传；向导不宣称网络同步已经完成。
- 来源完整包以用户密码加密，独立保存在目标空间的迁移备份目录，可另存到文件。源空间不修改、不自动删除。整台服务器的 `backup_manifest` 归档不能直接作为个人 `manifest` 归档导入。

## 验证范围

新增后台回归覆盖独立目录约束、完整/增量副本、整个原数据卷删除后的恢复与删除重放、账本缺失拒绝启动、删除副本故障不确认、失败重试复用同一包。本机回归覆盖 7 版轮换、跨空间拒绝、缺图清单与完整导出拒绝、确定性迁移及餐次/收藏照片引用、预览后的并发修改拒绝、删除标记保留、拒绝未认证的绑定来源。

另以虚构十类业务记录和合成 JPEG 完成 Python 个人导出 → Swift 打开/迁移 → Swift 导出 → Python 导入预览，核对照片摘要、中文、未知营养、公斤值及重复迁移。实际执行结果、工具版本和未验证范围以本轮《测试与验收》记录为准；这不代替真实独立存储掉线、手机锁屏、设备丢失和目标部署恢复演练。
