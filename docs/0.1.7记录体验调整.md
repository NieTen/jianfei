# 0.1.7 记录体验调整

本次按用户的 11 项反馈调整现有 SwiftUI 页面与计算规则，保留已有账号、记录、体重单位偏好、HTTP 后台、AI 配置、健康读取和伙伴同步。

## 体重录入

- 日期放在第一项。从首页或饮食页选择历史日期后进入录入，使用所选日期；首页选择今天时使用今天。
- 默认带入截至所选日期最近一次体重。在录入页手动切换日期或可选测量时刻后清空重量，单位继续沿用本机设置。
- “重量”、数值、单位下拉在同一行，填写数字后标签继续可见。
- 取消“指定为当天代表体重”开关。手机、后台、伙伴摘要和趋势均按当天测量时间最晚的一条有效记录计算；旧记录的代表标记保留兼容，但不再影响优先级。
- 历史明细继续保留每次测量；编辑测量日期时同步更新记录归属日期，健康来源的原始时刻仍受保护。

## 记一餐

- 早餐、午餐、晚餐使用三个直接点选的按钮，默认按档案时区的当前时段选择：05:00～10:59 为早餐，11:00～16:59 为午餐，其余为晚餐。点击待补充餐次时直接打开对应餐次。
- 不再要求填写进餐时间。所选记录日期继承首页，记录时刻自动生成；编辑已有餐次保留原日期与时刻。
- 拍照和相册使用各自独立的按钮与展示状态。选中照片后读取并自动开始识别，读取失败会说明原因。
- 配置了可用 AI 并同意发送照片后，自动展示食物名称、预计重量、预计热量，以及本餐蛋白质、碳水和脂肪合计。结果直接放在餐次页面，核对后点击保存。
- 未配置 AI 时，本机识别仍只提供类别候选，不伪造重量或营养。页面保留 AI 设置入口及手动记录方式。
- 手动热量模式只填写本餐摄入的 kcal。没有输入的宏量营养素保留为空。
- 更多选项保留备注、照片同步、营养库、常用食物、食物明细、草稿、识别方式与远程任务处理；原有加餐、饮料和其他类型仍可使用。
- 待补充餐次点击后进入录入。“未进食”放在独立的其他操作中，不会因点击整行而自动标记。

## 趋势、差额与首次设置

- 趋势首页同时展示体重折线和摄入热量柱图，保留时间范围、体重均线及其他指标。
- 未记录餐食时，已记录摄入为零，能量差额继续按身体参数和已经过去的时间暂估。未记录餐次保持待补充，已确认但热量未知的食物继续保持未知。
- 摄入图表不把没有餐食记录的日期补成零热量，避免与明确记录的零摄入混淆。
- 首次启动依次填写身体信息、选择活动水平、连接可选的后台和 AI。年龄、身高、体重和公式性别参数逐项校验，缺失项同时提示。
- 初始化、体重与记餐输入页提供“收起键盘”按钮，方便数字输入后查看后续内容。
- 身体档案与初始体重通过同一数据库事务保存，完成后重开应用不再重复引导。已有身体信息完整的本机身份直接进入；旧版信息不足的身份进入补全流程。
- 未成年人自动使用记录模式；原有“仅记录，不估算消耗”选择继续保留。

## 验证范围

本地后台 46 项测试已通过。新增客户端回归覆盖时段餐次、仅热量餐次、识别结果替换、最新体重、无餐差额、图表缺失日期、历史统计日、初始化校验与持久化。新增独立界面测试目标，实际点击首次引导、体重保存与重进、手动热量保存和系统相册入口。参考图改版前的 52 项客户端回归通过；点击流程的脚本输入问题已定位并修正，尚未复跑。用户随后要求按参考图调整样式，并明确等确认改完后统一打包，因此本轮不再触发构建。参见《参考图界面调整》和《测试与验收》。

后台云端 Python 3.11、3.13 各 46 项测试通过，耗时分别为 13.080、8.903 秒。群晖镜像 AMD64、ARM64 各 46 项回归通过，耗时分别为 12.601、214.712 秒，同时完成无密钥注册、登录、HTTP、HTTPS、实例身份与重建后数据保留检查。ARM64 使用 QEMU。已发布 latest 镜像索引摘要为 sha256:88628d9fc0b4eed7863ca7318ab8bb0dbd661afd32fbc107bd276451de8d4a14。[后台测试记录](https://github.com/NieTen/jianfei/actions/runs/42371278296)；[群晖镜像发布记录](https://github.com/NieTen/jianfei/actions/runs/42371278333)。

照片估算使用真实接口时仍取决于已配置的模型。相机、Sideloadly 最终签名、HealthKit 和 Watch 配对须在实际设备继续验收。部署时同时更新 App 和 NAS 后台，沿用原项目与数据卷。
