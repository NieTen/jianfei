# 部署与运行

## 1. 环境与目录

- 后台镜像使用 Python 3.13，Windows 开发环境使用 Python 3.11。
- 后台生产依赖已锁定在 backend/requirements.txt。
- 客户端最低支持 iOS 17，Watch 最低支持 watchOS 10。
- Docker 部署需要正在运行的 Linux 容器引擎及 Docker Compose。
- iPhone、Watch 构建需要 Mac、Xcode、对应系统 SDK 和签名团队。

| 目录或文件 | 用途 |
| --- | --- |
| backend/app | 后台服务与数据库迁移 |
| backend/tests | 自动化回归与真实 HTTP 测试 |
| ios/BingJian | iPhone 源码 |
| ios/BingJianWatch | Watch 源码 |
| ios/BingJianTests | 客户端 XCTest |
| ios/BingJian.xcodeproj | 已生成的 Xcode 工程 |
| tools/generate_xcode_project.py | 工程与资源生成器 |
| compose.yaml | API、Caddy 与持久化卷 |
| .env.example | 部署变量模板 |

## 2. Docker 启动

### 准备配置

在 PowerShell 7 执行。

~~~powershell
Set-Location 'D:\codeing\jianfei'
Copy-Item .env.example .env
New-Item -ItemType Directory -Path secrets -Force
~~~

修改 .env 中四个地址变量，以下地址仅为示例。为部署机器保留固定内网地址。

~~~dotenv
SERVER_NAME=192.168.1.10
LAN_BIND=192.168.1.10
HTTPS_PORT=8443
PUBLIC_URL=https://192.168.1.10:8443
~~~

设置至少十位的独立 BACKUP_PASSWORD 后，后台按配置时区每日执行备份。密码应另外保存。

### 启动服务

~~~powershell
docker compose config --quiet
docker compose up -d --build
docker compose ps
docker compose logs --tail 100 api
docker compose exec api python -m app.cli status
~~~

API 仅在 Compose 内部监听 8000。iPhone 使用 Caddy 暴露的 HTTPS 端口。后台运行一个 Uvicorn worker，应用实例锁保护同一数据目录。

API 与 Caddy 分别设置 512MiB、128MiB 内存预算。AI 推理服务的资源另行配置。

### 开户

~~~powershell
docker compose exec api python -m app.cli enrollment
~~~

该命令生成一次性开户凭据，有效期二十四小时。每位新用户分别生成一个凭据。在 App 注册页填写用户名、密码、称呼及开户凭据。注册后保存一次性展示的恢复凭据。

BOOTSTRAP_CODE 为空时会生成初始凭据文件，日常使用上述命令取得新的开户凭据。

健康检查路径为 /api/v1/health，接口文档路径为 /api/docs。业务接口需要登录后的访问令牌。

## 3. HTTPS 与内网连接

Caddy 为 SERVER_NAME 生成内网证书，根证书存放在 caddy_data 卷。导出根证书。

~~~powershell
docker compose cp caddy:/data/caddy/pki/authorities/local/root.crt ./root.crt
Get-FileHash -LiteralPath ./root.crt -Algorithm SHA256
~~~

由部署者通过可信渠道将根证书及其校验值交给使用者。使用者核对后在 iPhone 安装描述文件，并在系统的证书信任设置中开启该根证书的完全信任。

App 使用系统 HTTPS 信任验证，地址变化时清理原登录会话，并在同步握手时验证服务实例身份。修改 SERVER_NAME 或内网 IP 后，需要检查证书包含的新地址。

生成包含实例身份和证书指纹的配对信息。

~~~powershell
docker compose cp ./root.crt api:/data/tmp/root.crt
docker compose exec api python -m app.cli pairing --certificate /data/tmp/root.crt
~~~

将输出的 JSON 通过可信渠道交给使用者。在 App 的“核验服务身份与证书指纹”中粘贴，核对地址、实例身份和 CA 指纹，然后验证并保存。也支持扫描内容为该 JSON 的二维码。

App 在系统证书链验证通过后检查已保存的证书指纹，并在登录时校验服务实例。此处 CA 指纹基于证书 DER 内容，根证书文件的 Get-FileHash 校验值用于文件传输核对。[Apple 服务信任验证](https://developer.apple.com/documentation/foundation/performing-manual-server-trust-authentication)

首次启动填写形如 https://192.168.1.10:8443 的地址，点击测试并保存。后续启动会读取已保存地址。登录后，在“个人同步”中开启记录同步。

可选内网发现需要在宿主网络发布 mDNS。Docker 桥接网络中的 mDNS 通常无法直接传播到局域网，因此提供宿主机命令。

~~~powershell
Set-Location 'D:\codeing\jianfei\backend'
..\.venv\Scripts\python.exe -m app.cli advertise --address 192.168.1.10 --hostname bingjian.local --port 8443
~~~

hostname 应能解析到部署机器，且与部署证书匹配。也可直接在 App 填写 IP。

## 4. AI 接口与模型

### App 个人配置

打开“我的 → AI 与个性化估算 → 设置 AI 接口、密钥与模型”。

1. 填写 API 根地址或完整的 /responses 地址。
2. 填写自己的 API Key。
3. 选择私有后台代发或手机直连。
4. 点击读取模型列表，选择模型，也可手动填写模型标识。
5. 按接口能力开启严格 JSON 结构化输出，设置输出上限。
6. 对外部处理接口确认照片发送授权，然后保存。

地址、模型和选项保存到本机。API Key 保存到 iOS Keychain。后台代发时，当前用户的配置及加密密钥同时保存在后台数据库，重启后保留。模型列表缓存五分钟。

模型列表读取使用 GET /models。识别使用 POST /responses，图片采用 input_image，文本采用 input_text。结构化输出使用 text.format，处理原始 output 消息中的 output_text、refusal 及 incomplete 状态。请求设置 store 为 false。模型返回结果需要用户核对后才能计入正式摄入。[图片输入说明](https://developers.openai.com/api/docs/guides/images-vision?api-mode=responses) [结构化输出说明](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses)

测试连接验证接口和模型列表。模型是否支持图片及所选 JSON 输出模式，需要实际识别验证。第三方接口未提供 /models 时，可以手动填写其模型标识。

后台配置页面留空密钥会保留已有密钥。更换接口地址时应填写该接口的密钥。更换提供方或模型后需要重新确认外部照片授权。

手机直连使用 HTTPS。后台代发可接入部署者允许的内网服务，AI_ALLOWED_HOSTS 使用逗号分隔主机名或 IP。AI_URL 对应的默认上游主机会加入允许列表。

### 后台默认配置

也可在 .env 配置默认上游。

~~~dotenv
AI_PROTOCOL=responses
AI_URL=https://api.openai.com/v1
AI_MODEL=填写你的接口实际提供的图像模型标识
AI_KEY=填写你的密钥
AI_EXTERNAL=true
~~~

应用用户可保存自己的接口和模型覆盖默认值。默认上游密钥只由后台使用。

配置自建内网模型时，将主机加入 AI_ALLOWED_HOSTS，并按真实数据流设置 AI_EXTERNAL。内网代理转发到外部提供方时应开启外部处理标记。

任务已经发出后发生超时或服务中断，状态可能为 unknown。先查询原任务状态，再决定重试。服务重新启动会恢复内部导出、删除任务，将中断的外部识别任务标为待用户确认。

## 5. Windows 本地开发

首次安装依赖。

~~~powershell
Set-Location 'D:\codeing\jianfei'
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements.txt
~~~

启动 API。

~~~powershell
Set-Location 'D:\codeing\jianfei\backend'
$env:DATA_DIR = 'D:\codeing\jianfei\data'
$env:PUBLIC_URL = 'https://你的内网地址:8443'
..\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1 --no-access-log
~~~

另开 PowerShell 7 窗口，在相同 DATA_DIR 下生成开户凭据。

~~~powershell
Set-Location 'D:\codeing\jianfei\backend'
$env:DATA_DIR = 'D:\codeing\jianfei\data'
..\.venv\Scripts\python.exe -m app.cli enrollment
~~~

Python 本地启动通过进程环境变量提供配置，.env 由 Compose 读取。手机接入需配置 HTTPS 反向代理。

执行测试。

~~~powershell
Set-Location 'D:\codeing\jianfei\backend'
$env:PYTHONIOENCODING = 'utf-8'
..\.venv\Scripts\python.exe -m unittest discover -s tests -v
~~~

当前机器曾配置 SOCKS 代理，导致 pip 缺少 SOCKS 支持。若再次出现相同报错，可在当前安装窗口临时清空 ALL_PROXY、HTTP_PROXY、HTTPS_PROXY、PIP_PROXY，并使用 pip 的 --isolated 参数。

## 6. iPhone 与 Watch 构建

将整个项目复制到 Mac。Xcode 工程引用后台目录中的共享食物 JSON Schema，需要保留目录关系。

1. 打开 ios/BingJian.xcodeproj。
2. 在 Project 的 Build Settings 修改 APP_BUNDLE_IDENTIFIER 为自己的标识。
3. 在 iPhone 与 Watch Target 的 Signing & Capabilities 选择签名团队。
4. 确认 HealthKit 能力及相应描述，远程通知启用时确认 Push Notifications 能力。
5. 选择 iPhone 模拟器或真机运行 BingJian Scheme。
6. 在配对 Watch 运行 BingJianWatch，验证快捷记录和离线传输。

Watch Target 使用主应用标识加 .watchkitapp，伴随应用标识通过构建设置自动展开。Release 使用 production APNs 环境，Debug 使用 development。

查询本机模拟器并执行单元测试。

~~~bash
xcrun simctl list devices available
xcodebuild -project ios/BingJian.xcodeproj -scheme BingJian \
  -destination 'platform=iOS Simulator,id=替换为设备UUID' \
  CODE_SIGNING_ALLOWED=NO test
~~~

新增 Swift 文件后可重新生成工程。生成器会覆盖自动生成的工程、Info.plist、entitlements 和图标资源，已有签名设置应先保存。

~~~powershell
Set-Location 'D:\codeing\jianfei'
.\.venv\Scripts\python.exe tools/generate_xcode_project.py
~~~

HealthKit 数据可用性、后台唤醒、相机、通知和 Watch 配对需要真机验收。2026 年 11 月 4 日已通过云端 Xcode 16.4 完成 iPhone 与 Watch 的 Release 真机目标编译并生成待签名 IPA。Windows 安装步骤见同目录《Windows安装iOS测试包.md》，签名安装和上述平台运行验收仍待执行。

## 7. 可选外部服务

### 营养库

配置 FOOD_API_KEY 后启用 USDA FoodData Central 查询。本机常用食物可离线搜索。没有外部密钥时，界面仍支持手动记录和个人食物库。

### APNs

将 Apple 的 .p8 密钥放入项目 secrets 目录，确保容器运行用户可读。

~~~dotenv
APNS_KEY_FILE=/run/secrets/AuthKey_你的标识.p8
APNS_KEY_ID=你的KeyID
APNS_TEAM_ID=你的TeamID
APNS_TOPIC=你的主应用BundleIdentifier
APNS_SANDBOX=true
~~~

设置 APNS_SANDBOX 与客户端签名环境一致。用户还需在 App 提醒设置中开启远程通知。推送正文采用通用鼓励文案，详细内容在 App 中鉴权读取。

## 8. 备份与恢复

### 自动备份

配置 BACKUP_PASSWORD 后，后台每天按 BACKUP_HOUR 保存数据库快照与加密附件引用，保留三十天。附件按内容哈希复用，加密对象存放在 backups/objects。每次备份会在隔离目录解密、检查文件哈希和 SQLite integrity_check。

备份包含数据库、附件和恢复所需的内部加密密钥。独立删除账本保存在数据卷中，恢复旧备份时会重放后续删除意图，并使旧会话、同步纪元和共享授权失效。

复制增量备份时，应保存整个 backups 目录，包含 .bjar、.refs.json 和 objects。保留期清理会保留仍被有效备份引用的附件对象。修改备份密码后会建立新的加密对象命名空间，旧包继续使用旧密码。

使用 backup --full 可生成单文件完整包，适合单次迁移。用户在 App 中导出的个人加密包始终独立包含所选附件。

### 手动备份

运维命令需要独占实例锁，先停止 API。

~~~powershell
docker compose stop api
docker compose run --rm --no-deps api python -m app.cli backup --full
docker compose up -d api
docker compose cp api:/data/backups ./备份
docker compose cp api:/data/db/deletion-ledger.json ./备份/deletion-ledger.json
docker compose cp api:/data/db/deletion-intents.jsonl ./备份/deletion-intents.jsonl
~~~

从未发生删除时，独立账本文件可能尚未生成。发生删除后，应持续复制最新账本到独立保管位置，以便新机器恢复旧备份时继续执行删除要求。

### 恢复

先将待恢复的完整包复制到 API 的持久化数据卷，再执行恢复。

~~~powershell
docker compose stop api
docker compose cp 'D:\备份\需要恢复的文件.bjar' api:/data/tmp/restore.bjar
docker compose run --rm --no-deps api python -m app.cli restore /data/tmp/restore.bjar
docker compose up -d api
~~~

恢复会先验证包内容。当前目录已有用户数据时，会先生成安全备份。空机器恢复前，需把最新独立删除账本复制到 /data/db 对应位置。

恢复增量包时，同时复制其 objects 目录，并为 restore 传入 --objects /data/backups/objects，或将 objects 放在待恢复包的同级目录。

恢复结束后，用户重新登录、拉取一致性快照，并重新确认共享授权。全部个人数据删除后的旧设备还需要清理本机旧副本，再建立当前代际的同步基线。

### 数据卷与密钥

数据库、照片和内部密钥位于 app_data。Caddy 根证书位于 caddy_data。升级服务时保留这些卷。

在 Windows 检查 BitLocker 保护的数据盘，在 Linux 或 NAS 检查数据卷所在的加密文件系统及访问权限。备份密码、账号恢复凭据和外部服务密钥分开保管。

服务器操作系统管理员能够访问运行中的数据库和文件，部署者属于受信任主体。普通业务账号只能访问自己的数据及明确授权的共享范围。

## 9. 常见问题

| 现象 | 检查项 |
| --- | --- |
| Docker 提示找不到 docker_engine | 安装并启动 Docker Engine，Windows 可使用 Docker Desktop 或可用的远程引擎 |
| iPhone HTTPS 连接失败 | IP、端口、网络、防火墙、SERVER_NAME 与系统证书信任 |
| 新地址需要重新登录 | 核对服务实例后登录，账号本地库按实例和用户分别保留 |
| 模型列表返回 404 | 核对 API 根路径，或手动填写接口提供的模型标识 |
| AI 返回 400 | 核对模型图像能力、Responses 支持和结构化输出选项 |
| 内网 AI 地址被后台拒绝 | 检查 AI_ALLOWED_HOSTS |
| 服务重启后仍有识别待确认 | 查看 unknown 任务的原始状态，再决定是否重试 |
| 同步显示冲突或失败 | 在“同步状态与冲突”查看原因，合并或修正后重试 |
| 后台运维提示实例已占用 | 停止当前 API 后运行备份或恢复 |
| 删除请求离线待发送 | 连通原后台后优先重试，可通过独立删除回执查询 |
